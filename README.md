# URL Shortener

HTTP-сервис сокращения URL на Go без внешних зависимостей.

## Запуск


```sh
go run .
```

Адрес по умолчанию — `http://localhost:8080`.


### POST /shorten

```sh
curl -i -H "Content-Type: application/json" -d '{"url":"https://example.com/long/path?q=1"}' http://localhost:8080/shorten
```

Пример ответа, HTTP 200:

```json
{"short_url":"aB3d_9Xz","original_url":"https://example.com/long/path?q=1"}
```

`short_url` — идентификатор, а не полный адрес. Для перехода используйте
`http://localhost:8080/aB3d_9Xz`. Пример ID иллюстративный: сервис генерирует
случайный ID при каждом успешном сокращении, в том числе для повторного URL.


### GET /{short_url}

```sh
curl -i http://localhost:8080/aB3d_9Xz
```

Возвращает HTTP 302 с исходным URL в заголовке `Location`.

### Ошибки

Ошибки возвращаются как `{"error":"описание"}`:

| Статус | Причина |
| --- | --- |
| 400 | Некорректный JSON, отсутствующий или невалидный URL |
| 404 | Неизвестный идентификатор, пустой или вложенный путь |
| 405 | Неподдерживаемый HTTP-метод; допустимый указан в `Allow` |
| 413 | Тело запроса больше 1 МиБ |
| 500 | Ошибка генерации ID или исчерпание попыток при коллизиях |

Допускается один JSON-объект с полем `url` типа string. Неизвестные поля
и дополнительные значения после объекта отклоняются. URL должен содержать
схему `http` или `https` и непустое имя хоста. Пробельные и управляющие
символы запрещены, пробел в пути следует записывать как `%20`.
Если указан порт, он должен быть в диапазоне 1–65535.
DNS-запросы и проверка доступности сайта не выполняются.

## Устройство

- `shortener.go`: бизнес-логика, валидация и map с `sync.RWMutex`.
- `main.go`: маршрутизация, HTTP-обработчики и запуск сервера.
- `shortener_test.go`: table-driven тесты с `t.Run`, коллизии, ошибки генератора и конкурентный доступ.
- `handlers_test.go`: `httptest`, успешные и ошибочные запросы, полный HTTP-цикл.

ID содержит 8 URL-безопасных символов: 6 случайных байтов из `crypto/rand`
кодируются через base64 URL без padding. Проверка занятости и запись выполняются
под одной блокировкой, поэтому коллизия не перезаписывает существующий URL.
При коллизии генерация повторяется, максимум 16 попыток на запрос.

Данные хранятся только в памяти и теряются при перезапуске. Отдельные экземпляры
сервиса не разделяют хранилище. Неиспользуемые ссылки автоматически не удаляются.
